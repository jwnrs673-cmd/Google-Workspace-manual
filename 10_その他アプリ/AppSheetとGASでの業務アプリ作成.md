# その他アプリ：AppSheet と Google Apps Script での業務アプリ作成

> 対象アプリ: AppSheet / Google Apps Script（GAS）
> 最終更新日: 2026-07-20
> 作成・更新者: {氏名}

## 1. 概要

このマニュアルでは、当社の Google Workspace で使える 2 つの **内製アプリ開発ツール**、
**AppSheet（アップシート）** と **Google Apps Script（グーグル アップス スクリプト＝GAS）** について、
**何ができるのか・どちらを使えばいいのか・作るときの社内ルール** を説明します。

ポイントは次の 3 つです。

1. **AppSheet は「コードを書かずに」スプレッドシートから業務アプリを作れる**（在庫管理・点検・申請など）
2. **GAS は「JavaScript で」Google のアプリ同士を自動連携させる**（定型メール送信・集計・通知など）
3. **業務アプリの内製は便利だが、扱うデータ・共有範囲・作った後の引き継ぎを間違えると会社のリスクになる** ため、必ず社内ルールに沿って作る

> 💡 いずれも **Enterprise Standard / Frontline Starter に含まれる**ため、追加費用なしで始められます（AppSheet は **Core** ライセンス。詳細は「2-5」）。だからこそ、誰でも気軽に作れてしまう反面、**「野良アプリ」が乱立して管理不能になる**危険があります。理由もあわせて説明するので、必ず最後まで読んでください。

## 2. 機能の説明

### 2-1. AppSheet とは（ノーコードで業務アプリを作る）

**AppSheet** は、**スプレッドシートなどの「表」をデータ源にして、スマホ／PC で使える業務アプリを、コードを書かずに作れる**ツールです。

| 項目 | 内容 |
| --- | --- |
| **データ源** | Google スプレッドシート、Google フォーム、クラウドSQL など（当社では原則スプレッドシート） |
| **作り方** | 表を選ぶ → AppSheet が自動でアプリの画面を生成 → 見た目や動作を設定 |
| **使う人** | スマホアプリ（iOS/Android）またはブラウザから利用 |
| **得意なこと** | 一覧・登録・編集フォーム、写真添付、地図、承認フロー、通知 |

**向いている業務の例**

- 店舗の **在庫・発注管理**、**設備・什器の点検チェック**
- **各種申請・報告**（備品申請、日報、クレーム受付など）
- 現場での **写真付き報告**（破損・清掃・陳列状況など）

### 2-2. AppSheet でアプリを作る大まかな手順

1. データにする **Google スプレッドシート**を用意する（1 行目を項目名にする）
2. [appsheet.com](https://www.appsheet.com/) にアクセスし、**会社アカウントでログイン**する
3. 「Create」→「App」→「Start with your own data」から、対象のスプレッドシートを選ぶ
4. AppSheet が自動で一覧・入力フォームを生成する
5. 画面（Views）、入力項目（Columns）、動作（Actions/Bots）を調整する
6. テスト後、「**Users**」タブで **利用者を追加**して共有する（＝配布）

（必要に応じてスクリーンショットを `_assets/` から参照）

### 2-3. Google Apps Script（GAS）とは（Google アプリを自動化する）

**Google Apps Script（GAS）** は、**JavaScript を使って Google Workspace の各アプリを操作・連携させる**プログラミング環境です。ブラウザだけで書けて、サーバー準備は不要です。

| 項目 | 内容 |
| --- | --- |
| **書く言語** | JavaScript ベースの独自スクリプト |
| **操作できるもの** | スプレッドシート、ドキュメント、Gmail、カレンダー、ドライブ、フォーム、Chat など |
| **実行のきっかけ** | 手動実行、時間主導（毎日◯時など）、フォーム送信時、シート編集時 など |
| **得意なこと** | 定型作業の自動化、集計、定期メール／通知、アプリ間のデータ連携 |

**向いている業務の例**

- スプレッドシートの内容を **毎朝集計してメール／Chat 通知**する
- **フォーム送信をトリガー**に、自動返信メールや台帳への転記を行う
- カレンダーやドライブと連携した **定型処理の自動化**

### 2-4. GAS を書く大まかな手順

1. スプレッドシートを開き、メニューの **「拡張機能」→「Apps Script」** を開く
2. エディタでスクリプト（関数）を書く
3. 書いたコードは、**生成 AI（Gemini など）に内容をチェックさせ、問題がないか確認する**（意図しない情報送信・削除・脆弱性などがないか。「3. 社内ルール」参照）
4. **保存 → 実行**し、初回は表示される **権限（アクセス許可）の確認**を承認する
5. 定期実行したい場合は、左メニューの **「トリガー」** で実行タイミングを設定する
6. 動作を確認し、必要なら共有・引き継ぎ手順を残す

> ⚠️ 実行時に「このアプリは Google で確認されていません」と表示されることがあります。これは**自分で書いたスクリプトを自分で承認する**ための画面です。**他人から送られてきた不明なスクリプトを安易に承認しない**でください（「3. 社内ルール」参照）。

### 2-5. 当社のライセンスで使える範囲

当社のエディションと、内製ツールの利用可否は次のとおりです。

| ツール | Enterprise Standard | Frontline Starter | Cloud Identity Free |
| --- | --- | --- | --- |
| **AppSheet Core** | ◎ 追加料金なしで利用可 | ◎ 追加料金なしで利用可 | × 含まれない（別契約が必要） |
| **Google Apps Script** | ◎ 利用可 | ◎ 利用可（Sheets 等の範囲内） | △ Gmail・Drive 等の対象サービスがないため実質的に限定的 |

- **AppSheet Core** は Enterprise Standard・Frontline Starter に含まれます。ただし Core は機能に上限があり、**外部データベース接続や一部の高度な自動化・機械学習機能は上位ライセンス（Enterprise Plus 等）が必要**になる場合があります。
- **GAS** は基本的に無償で使えますが、**1 日あたりの実行時間・メール送信数などに割り当て（クォータ）上限**があります。大量送信・大量処理を行う設計は、上限に達して止まることがあります。

> 📌 どのエディションかは [アカウントの利用ルール](../00_共通ルール/アカウントの利用ルール.md) や [Googleワークスペースとは](../00_共通ルール/Googleワークスペースとは.md) を参照。不明な場合は上長へ確認してください。

### 2-6. どちらを使うべきか（使い分けの目安）

| こんなとき | 向いているツール |
| --- | --- |
| 画面から**入力・一覧・編集**する業務アプリが欲しい（在庫、点検、申請など） | **AppSheet** |
| スマホで**写真を撮って報告**させたい | **AppSheet** |
| プログラミングは避けたい／現場の人が使う | **AppSheet** |
| 定型作業を**自動で・定期的に**動かしたい（集計・通知・メール） | **GAS** |
| フォーム送信やシート編集を**きっかけに処理**したい | **GAS** |
| 細かい条件分岐や外部サービス連携など**複雑な処理**が必要 | **GAS** |

> 💡 両者は組み合わせられます。例：AppSheet で現場が入力 → スプレッドシートに蓄積 → GAS が毎朝集計して本部に Chat 通知、という連携も可能です。

## 3. 社内ルール

内製アプリ（AppSheet / GAS）は便利ですが、**会社のデータを扱い、他の人も使う「業務システム」**です。個人の思いつきで作って放置すると、情報漏えい・データ破損・引き継ぎ不能といった問題につながります。次のルールを必ず守ってください。

- **やること**
  - **作る前に上長へ相談・申請**する（対象業務・扱うデータ・利用者範囲を伝える）
  - データ源のスプレッドシート等は、**必ず「共有ドライブ」に置く**（会社の資産として残す。[ドライブのルール](../02_Googleドライブ/マイドライブと共有ドライブの使い分け・共有ルール.md)参照）
  - アプリ・スクリプトの **利用者（共有範囲）は必要最小限**に絞る
  - **作成者・目的・更新履歴を記録**し、引き継げる状態にしておく（作った本人しか分からない「属人化」を避ける）
  - GAS は**自分で内容を理解して書いた／レビューしたスクリプトだけ**を承認・実行する
  - **GAS でアプリ・コードを作成したときは、コード内容に問題がないか、生成 AI（Gemini など）によるチェックを必ず入れる**（意図しない情報送信・削除・脆弱性などがないか確認する）
  - 本番運用の前に、**テスト用データで動作確認**する
- **展開（配布）前の承認 ― 重要**
  - 次のいずれかに当てはまる AppSheet／GAS のアプリは、**必ず上長、ならびにコミットメント等で社長の承認を得たうえで展開（配布・本番運用）する**こと。
    - **個人情報を取り扱う**場合（従業員情報、顧客情報、クレーム情報など）
    - アプリに**登録した情報が漏洩した際に、会社にリスクが生じる**ような場合（機密情報・信用・法的責任に関わる情報など）
  - 承認を得る前に、対象アプリを**利用者へ配布したり本番運用を開始したりしない**
- **漏洩するとマズいデータを扱うアプリのアクセス制限 ― 重要**
  - 漏洩すると会社にリスクが生じるデータ（個人情報・機密情報など）を扱うアプリは、**「リンクを知っている全員」が閲覧できる状態にせず、パスワード等のアクセス制限を設定したうえで展開する**こと。
    - AppSheet：共有は**「Users」タブで特定の利用者を指定**し、社内ドメイン限定・サインイン必須にする。「リンクを知っている全員」での公開はしない。
    - GAS の Web アプリ（`doGet`/`doPost` で公開する場合）：アクセス権を**「全員（匿名含む）」にせず、「組織内のユーザー」または特定ユーザーに限定**する。
    - データ源のスプレッドシート等も、**「特定の人を指定」**で共有し、パスワード保護や共有ドライブの権限で閲覧範囲を絞る。
  - **誰でもリンクだけで開ける状態のまま、機密データを扱うアプリを配布しない**
- **やってはいけないこと**
  - 個人の **マイドライブや個人アカウント**をデータ源／保存先にしない（退職・異動で消える・引き継げない）
  - **個人情報・機密情報**（従業員情報、クレーム、顧客情報など）を扱うアプリを、**上長・社長の承認なしで展開しない**
  - アプリやデータを **「リンクを知っている全員」／社外**に安易に共有しない
  - **出所不明の GAS スクリプトをコピペして実行・承認しない**（悪意あるコードで情報が抜かれる恐れ）
  - AppSheet アプリを **個人アカウント（〜@gmail.com）で作らない**（会社の管理下から外れる）
- **例外・注意点**
  - 個人情報・機密情報を扱う、**全社／多店舗に配布する、外部と連携する**アプリは、**必ず事前に上長、ならびにコミットメント等で社長の承認**を得る
  - 作成者が**異動・退職**する場合は、アプリの所有権・スクリプトを**後任へ引き継ぐ**（所有者が消えるとアプリが止まる）
  - GAS の **クォータ（実行時間・送信数の上限）** を超える大量処理は避け、必要なら上長に相談する
  - AppSheet Core で足りない機能（外部DB接続など）が必要な場合は、**自己判断で契約せず**上長へ相談する

## 4. よくある質問（FAQ）

**Q. プログラミングの知識がなくてもアプリは作れますか？**
A. **AppSheet はコードを書かずに**作れます。まずはスプレッドシートを用意し、AppSheet で自動生成された画面を調整するところから始めてください。GAS は JavaScript の知識が必要です。

**Q. AppSheet や GAS は無料で使えますか？**
A. Enterprise Standard・Frontline Starter には **AppSheet Core と GAS が追加費用なしで含まれます**。ただし Core の機能上限や GAS のクォータ（上限）があります。Cloud Identity Free では AppSheet は使えません。

**Q. データはどこに置けばいいですか？**
A. **必ず共有ドライブ**に置いてください。個人のマイドライブに置くと、作成者の退職・異動時にアプリごと使えなくなる危険があります。

**Q. 作ったアプリを店舗のみんなに配りたい。**
A. まず**上長に相談**してください。多店舗・全社配布は影響範囲が大きいため、承認とデータ・共有設計の確認が必要です。AppSheet では「Users」タブで利用者を追加して配布します。

**Q. 従業員情報やクレーム情報を扱うアプリを作ってもいい？**
A. **個人情報・機密情報を扱うアプリは、上長・社長の承認が必須**です。自己判断で展開しないでください。共有範囲も厳しく絞る必要があります。**個人情報を扱う場合や、登録情報が漏洩すると会社にリスクが生じる場合は、展開（配布・本番運用）の前に、上長ならびにコミットメント等で社長の承認**を得てください（「3. 社内ルール」参照）。

**Q. 漏洩するとマズいデータを扱うアプリは、どう配布すればいい？**
A. **「リンクを知っている全員」が閲覧できる状態にしないでください。** AppSheet は「Users」タブで特定の利用者を指定し、社内ドメイン限定・サインイン必須にします。GAS の Web アプリはアクセス権を「組織内のユーザー」や特定ユーザーに限定し、匿名アクセスを許可しません。データ源のスプレッドシートも「特定の人を指定」で共有し、パスワード等でアクセスを制限したうえで展開してください（「3. 社内ルール」参照）。

**Q. どんなときに上長・社長の承認が必要ですか？**
A. AppSheet／GAS のアプリで、**①個人情報を取り扱う場合**、または **②アプリに登録した情報が漏洩したときに会社にリスクが生じる場合**は、**展開前に必ず上長、ならびにコミットメント等で社長の承認**を得てください。承認前に配布・本番運用を始めてはいけません。

**Q. GAS でコードを書いたら、そのまま動かしていい？**
A. いいえ。**GAS でアプリ・コードを作成したときは、生成 AI（Gemini など）でコード内容に問題がないかチェック**してから使ってください。意図しない情報送信・データ削除・脆弱性などが混ざっていないかを確認するためです。自分で理解できないコードは実行・承認しないでください。

**Q. ネットで見つけた GAS のコードを貼り付けて使ってもいい？**
A. **内容を理解できないコードは実行・承認しないでください。** 悪意あるスクリプトだと、あなたの権限でメールやファイルにアクセスされる恐れがあります。不安な場合は上長に確認してください。

**Q. 作った人が異動・退職したらどうなりますか？**
A. 所有者がいなくなるとアプリが止まったり編集できなくなります。**事前に後任へ所有権・スクリプトを引き継いで**ください。だからこそ、作成時に目的や作りを記録しておくことが大切です。

**Q. AppSheet と GAS、どちらを選べばいい？**
A. **入力・一覧・報告の「アプリ」なら AppSheet**、**集計・通知・メールの「自動化」なら GAS** が目安です（詳細は「2-6」）。両方を組み合わせることもできます。
